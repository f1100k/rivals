- Match prints live in the match-prints bucket only during voting; 6 approvals required to finalize, 6 rejections reset it.
- Admin test queue uses queue/matches region 'TESTE': separate matchmaking pool, finalize treats it as non-competitive, Discord publish/voice skip it.
- Kick ballots resolve under the match lock, pause drafting/finalization, archive removed membership separately and atomically claim same-pool FIFO replacements; inherited slots preserve draft rhythm, and bot provenance survives roster changes. A majority only moves the vote to pending_admin (match stays paused); removal happens solely in the admin-checked admin_decide_match_kick_gk RPC.
- Admin queue/match refresh goes through admin_refresh_inhouse_gk, which reuses the existing sweep/kick/draft/matchmaking functions instead of duplicating their rules.
- Public site links (Discord messages etc.) use SITE_URL from src/lib/links.ts so a domain change is one edit.
- Mix mode is a flag on matches set at matchmaking (mix_assign_teams_gk) when mix_active(); finalize treats is_mix like non-competitive and the Mix ranking is computed from completed is_mix matches, so the general MMR rules stay untouched. Mix matchmaking takes the same first-come 10 as normal and mix_assign_teams_gk computes per-position targets so every position splits within one between sides (checked by mix-positions.test.sql); per-player Mix ranking removals or outcome overrides (counts_as) go in mix_ranking_exclusions, never by editing match results.
- Discord account linking returns through an origin registered in the Discord app (discordRedirectFor), because Discord rejects unregistered redirect URIs and the old lovable.app domain forwards to the custom domain keeping the URL fragment.
- Seasons are started/finished only through admin-checked RPCs (one active at a time); finishing freezes rows in season_player_stats, then season_reset_progress zeroes rating/record/streaks and rank-reward high-water marks before the next season starts, so live profile counters always mean "current season". Rankings/match lists take an optional season id resolved by season_bounds (null = active), finished-season MMR ranking reads the snapshot, rank-up reward keys are season-scoped (rank_grant_key), and career totals = live counters + finished snapshots. Titles carry the season they were granted in and profiles read everything through get_player_seasons.
- Room codes are digits only (src/lib/room-code.ts), enforced in RoomCode input, the setRoomCode validator and set_room_code in the database, so text never reaches players as a code.
- Rivals League events (league_events) are weekly rankings independent of seasons: get_league_ranking tallies completed normal-queue matches (no Mix/bots/TESTE) by created_at inside the event window from match_players.delta, qualifies players at min_games, and admin_finish_league_event freezes the result in league_event_results; MMR itself is never touched. Ranking pages pick seasons and league events from one RankingViewPicker dropdown.
