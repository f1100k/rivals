# Component architecture
- Profile tags use audited admin catalog/grant RPCs, owner-only equip RPCs and one cached public equipped-tag projection beside names; colors use scoped CSS variables.
- Uploaded avatar frames use the shared runtime catalog with built-in fallback; all avatar, profile, shop, and fit views must resolve the same frame ID.
- Admin inventory writes use database-verified admin RPCs and audited, idempotent grant requests; fit editing remains on the existing allowlist.
- Frame publication atomically adds a priced shop item without public equip access; delivery to players is a separate action.
- Manual rating adjustments use an admin-checked, player-locked, idempotent RPC with an audit record; match records and win/loss counts stay unchanged.
- Shop editing and storefront share visibleShopItems ordering and count logic; hiding catalog items preserves purchases and frame ownership. All price changes and shop additions (frames, fonts, colors) go through the admin-only admin_save_shop_item RPC, which infers the item kind from its catalog table.
- Player video delivery is a root-level inbox using private recipient-readable storage and owner-scoped durable views; playback remains dismissible and starts muted for browser autoplay compatibility.
- Large video uploads use browser-only, dynamically loaded TUS chunks with progress rather than whole-file server function payloads.
- Prize events persist editable award amounts; payout RPCs snapshot event/name/amount and verify admin rights, with duplicate place-payment protection.- Site countdown and promo rotation are root-rendered widgets (fixed bottom-left/bottom-right from sm up, an in-flow strip under the header on phones so they never cover controls) reading public active rows; all writes go through admin-checked RPCs, and promo media lives in the public promos bucket with admin-only write policies.
- The Loja is open to every signed-in player (buy_shop_item only requires a session); admins edit prices inline on the Loja page and in Admin → Valores. Admin-unlockable features (banner) are checked through the has_feature() DB helper (admins always pass) in RLS/trigger/RPC code; the UI mirrors it with useHasFeature and the FEATURES list in src/lib/features.ts, which must match the DB check constraint.
- Player notifications are rows written only inside admin grant RPCs via the internal notify_user helper; the header bell reads owner-only rows and listens through one per-user realtime subscription.
- Likes are enabled in the active match Resultado tab once teams exist (room/voting/reporting/disputed/completed), because finished matches leave the queue screen. Like uniqueness is (giver, target, match) and "Curtido" state is read per match via get_my_match_liked_ids; profile supporter lists group by giver so keys stay unique.
- Batch admin adjustments (Admin → Pontos) reuse admin_adjust_rating per player for MMR and the admin-checked, idempotent admin_adjust_record RPC for win/loss totals; screenshot name reading is an admin-checked server function that only proposes matches, never writes ratings.
- Phone-only layout tweaks (here and in src/routes) use sm:/max-sm: overrides that restore the old desktop classes, keeping PC unchanged.
- Queue page chats (waiting room = null match, match room = match id) read/write only through get_queue_chat/send_queue_chat; room access, length, suspension and spam limits live in can_read_queue_chat and the send RPC, and the UI refreshes on one realtime subscription per room.
- Emblems mirror profile tags: admin-checked catalog/grant RPCs (grants carry a season), owner-only equip_emblem, one cached public get_equipped_emblems projection rendered before names, and images in the public emblems bucket written only by admins; background removal and trimming happen client-side (src/lib/emblems.ts) before upload.
- Name fonts mirror emblems: staff (is_staff) import files into the public name-fonts bucket and staff_save_font publishes them as kind='font' shop items; player_fonts rows come from buy_shop_item or staff_grant_font (granted_by set, and only gifted rows can be revoked), the shop treats any owned font as bought, owners pick one via equip_name_font, NameFontFaces in the root registers @font-face for the catalog, and every visible player name goes through PlayerName so the equipped font shows everywhere.
- Name colors mirror name fonts: staff create styles (name_colors: style + up to two hex colors) published as kind=name_color shop items, player_name_colors come from buy_shop_item or staff_grant_name_color (gifted rows revocable), owners pick one via equip_name_color, and PlayerName merges the equipped font and color (nameColorStyle in src/lib/name-colors.ts) so both show everywhere.
